# Supabase につなぐ

設定が空のあいだ、サイトは「この端末だけ」のアカウントで動きます。
以下をやると、端末をまたげる本物のアカウントに切り替わります。

所要時間はだいたい10分です。

## 1. プロジェクトを作る

[supabase.com](https://supabase.com) で新しいプロジェクトを作ります。
リージョンは近いところ（Tokyo など）を選んでください。

## 2. テーブルとポリシーを入れる

管理画面の **SQL Editor** に [`schema.sql`](schema.sql) の中身を貼って実行します。

これで入るもの:

| | |
|---|---|
| `public.profiles` | 公開の名札。ハンドル名・表示名・成績 |
| RLS | 読むのは誰でも可、書き換えは自分の行だけ |
| トリガ | 登録されたら名札を1枚自動で作る |

**メールアドレスは `profiles` に置いていません。** 公開読みを許すテーブルなので、
置いた時点で誰でも読めてしまいます。メールは Supabase 側の `auth.users` に
留めてあり、こちらからは触りません。

## 3. 鍵をサイトに書く

管理画面の **Project Settings → API** から2つ写して、
[`../assets/config.js`](../assets/config.js) に入れます。

```js
window.PB.CONFIG = {
  supabase: {
    url: 'https://xxxxxxxxxxxx.supabase.co',
    anonKey: 'eyJhbGciOi...'
  }
};
```

`anon` キーは**公開してよい鍵**です。ブラウザに配る前提で作られていて、
実際にできることは RLS が決めます。リポジトリに入れて構いません。

**`service_role` キーは絶対に置かないでください。** こちらは RLS を素通りします。

## 4. メール確認をどうするか

Supabase は既定で「確認メールのリンクを開くまでログインできない」設定です。

- **そのまま使う** ── 登録すると「確認メールを送りました」と出ます。安全側
- **切る** ── Authentication → Providers → Email の *Confirm email* を外す。
  すぐ使えるようになりますが、誰でも他人のメールアドレスで登録できるようになります

しばらく自分だけで使うなら、切っておくほうが楽です。
人に公開する段になったら戻してください。

## 5. 確かめる

サイトを開いて新規登録します。うまくいっていれば:

- ヘッダーに表示名が出る
- マイページの右上が **Supabase**（この端末のみ、ではなく）になる
- Supabase の Table Editor で `profiles` に1行増えている
- 別の端末・別のブラウザから同じメールとパスワードで入れる

## 分かっている制限

- **退会はこの画面からはできません。** `auth.users` の削除には管理権限が要り、
  クライアントからは行えないためです。押すとその旨が出ます。
  消すときは Supabase の Authentication → Users から
- **パスワードの再発行はまだ画面がありません。** REST の口
  （`POST /auth/v1/recover`）はあるので、足すのは難しくありません
- ハンドル名は登録時に決めたきりで、あとから変えられません。表示名は変えられます

## 動かないときに見るところ

| 症状 | たいていの原因 |
|---|---|
| 「権限がありません」 | RLS のポリシーが入っていない。`schema.sql` を流し直す |
| 「サーバーに接続できませんでした」 | `url` の綴り違い、または末尾に余計な `/` |
| 登録できるのに名札ができない | トリガが入っていない。`schema.sql` の後半だけ流し直す |
| 「確認がまだ済んでいません」 | 上の 4 を参照 |
