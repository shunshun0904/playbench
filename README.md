# shunshun0904

個人サイト。仕事とは別に、自分で確かめたことを置いておく場所です。

<https://shunshun0904.github.io/playbench/>

棚は3つ。上のタブで切り替えます。

| タブ | ページ | 中身 |
|---|---|---|
| 自己紹介 | [`index.html`](index.html) | 自己紹介・職務経歴・研究業績。中身は `data/profile.js` に書く |
| ボードゲーム | [`games.html`](games.html) | ボードゲーム2作の自主研究。遊べる |
| 経済 | [`macro.html`](macro.html) | 株式投資のために見ているマクロ経済指標。出どころと取得日つき |

- 数値はすべて出典つき。**出典のない数字は載せません**
- 勝率は必ず**互角の線つき**。4人戦なら .250
- リポジトリ名が `playbench` なのは、最初にボードゲームだけで始めたときの名残です

## マクロ経済指標

`data/macro.js` の `INDICATORS` が「何を見るか」を決め、取ってくるのは道具です。

```sh
ALPHAVANTAGE_KEY=xxxx node tools/fetch-macro.mjs          # 取って書き換える
ALPHAVANTAGE_KEY=xxxx node tools/fetch-macro.mjs --print  # 書き換えず出すだけ
```

鍵は <https://www.alphavantage.co/support/#api-key> で無料で取れます（1日25回）。

各指標には**掲載元（一次資料）のリンク**を添えています。図より先に置いてあります ──
数字そのものより、どこが出しているかのほうが先に要るためです。PDF には印を付けて、
押す前に分かるようにしています。

紹介文の直下に**一覧表**を置いています（項目・出典元・リンク・直近データ・次回公表）。
項目名を押すと下のカードへ飛びます。表と下のカードは同じ `INDICATORS` から組むので、
片方だけ古くなることはありません。

### 公表予定と、表の色分け

表の「次回公表」は、**近いものほど地が濃く**なります。いちばん近い1件は
日付そのものも朱で書きます。日次で出るもの（10年国債利回り）は「次の1日」が
無いので色を持ちません。

濃さは日数の差ではなく**順位**で決めます。公表が固まる月半ばでも間があく
月末でも、同じ幅で読めるようにするためです。順位は日付ごとに振るので、
同じ日に出るものは同じ濃さになります。

日付は `data/releases.js` にあり、**先の予定をまとめて持ちます**。
画面は今日以降で最初の1件を「次」として使うので、日が変わるだけで
ひとりでに繰り上がります。配備し直す必要はありません。

```sh
CALENDAR_ICS='https://calendar.google.com/calendar/ical/…/basic.ics' npm run calendar
```

URL は Google カレンダーの設定 →「カレンダーの統合」→
**「非公開URL（iCal形式）」**。カレンダーを公開する必要はありません。
この URL 自体が鍵なので、リポジトリには置かず GitHub の Secrets
（`CALENDAR_ICS`）に入れます。

[`.github/workflows/calendar.yml`](.github/workflows/calendar.yml) が
**毎日これを走らせ**、変化があれば `data/releases.js` をコミットします。

拾うのは `data/macro.js` の `release.match` に当たる予定だけです
（`['日本', 'マネタリーベース']` なら、件名に両方入っているものだけ）。
カレンダーには私用の予定も入っているので、**当たらないものは読み捨てて、
ファイルにも記録にも残しません**。1件も拾えなかったときは書き換えません
（取得に失敗しただけなのに、手元の予定を消すのを避けるため）。

**先の予定が尽きた指標は「予定なし」と出し、表の下でそう言います。**
黙って色が消えるのがいちばん困るためです。カレンダー側に足せば戻ります。

**図を持たない項目もあります。** Alpha Vantage に無い統計（日本の物価・マネタリー
ベース、PCE、ミシガン大、ベージュブック）は、掲載元へのリンクだけを置いています。
`fn` が無いものがそれで、取得の道具も飛ばします。

| | 掲載元 |
|---|---|
| 米 政策金利 / 10年国債利回り | FRB（FOMC 日程・H.15） |
| 米 CPI / 雇用統計・失業率 | BLS（公表文・PDF・公表予定） |
| 米 PCE | BEA |
| ミシガン大 消費者信頼感 | University of Michigan |
| 米 ベージュブック / マネーストック | FRB |
| 日本 全国CPI | 総務省統計局 |
| 日本 企業物価（PPI・輸出入） | 日本銀行 |
| 日本 マネタリーベース | 日本銀行 |

BGG のときと同じで、**手元で取る → JSON をコミットする → サイトはそれを読む**、
に統一しています。CI から外部APIを叩くと詰まりやすいためです。
いつ時点の数字かは `fetched` に残り、画面にも出ます。
**まだ取っていない指標は、取っていないと表示します。**

## 見た目について

**既定は黒**です。素の `:root` が黒の地で、白は天のボタンで選んだときだけ。
端末の設定（`prefers-color-scheme`）は見ていません ── 見ていると、明るい設定の
人には白で出てしまい「既定は黒」になりません。選んだ結果は `localStorage` に
残るので、白にした人は次からも白です。

地は白と黒、灰も色味を持たせず無彩色でそろえています。もとは製図用紙と青焼き
（生成りの地に方眼、藍の地に白抜き）でしたが、方眼の罫が字の下を走って
読みにくかったので、地は無地にしました。

色は2つだけ役割を持ちます。

| | |
|---|---|
| 朱 | 押せるもの、いま言いたい一行、互角を超えた棒 |
| 藍 | 比較のための計測値 |

カードの表には**遊ぶために要るものだけ**を置き、相手をどう作ったかの話は
「この相手をどう作ったか」に畳んであります。開くと**実測プレート**が出ます。
0 から 1.000 の目盛りの上に互角の線が全行を貫いて1本立ち、
棒はその線と一緒でなければ読めないようにしてあります。

## 開発

外部依存はありません（検査に Playwright を使うときだけ入れます）。

```sh
node build.js                     # dist/playbench.html に1枚化
node test/shots.js                # 実ブラウザで検査
python3 -m http.server 8080       # ローカルで開く
```

検査は簡易サーバを立てて http で行います。

検査が見ているもの:

- コンソールエラーが出ないこと、横スクロールが出ないこと
- **端末が明るい設定でも、選んでいなければ黒で出ること**（既定が黒であること）
- ゲーム・段階・作りの各要素が全部組まれていること
- **棒の実幅が値と一致していること**
- **携帯の幅（430〜320px）でタブが3枚とも見えていること**
- 測定IDが無ければ外部へ1本も出さず、あれば読みに行くこと
- 追跡拒否（DNT）を出しているブラウザには読み込まないこと
- BGG の行が、重さ5点満点・評価10点満点の割合で描かれること
- 英語に切り替えても崩れないこと

黒・白・モバイルの3面を `dist/shots/` に撮ります。白の面は
`localStorage` に選択を入れてから開きます（端末の設定では白になりません）。

## 配備とキャッシュ

GitHub Pages は `Cache-Control: max-age=600` で配ります。`index.html` が
`assets/site.js` のような**変わらないURL**を参照していると、閲覧者のブラウザは
手元の古い写しを使い続けます。**配備は成功しているのに画面が変わらない**、という
形になります。実際、ゲームを1つ増やしたときにこれが起きました。

そこで配備のたびに、`tools/stamp-assets.mjs` が**全ページ**の自前ファイル参照へ
コミットの SHA を `?v=…` として打ちます。URLが変わるのでブラウザは必ず取り直します。

```sh
node tools/stamp-assets.mjs --check   # 版が付いているか確かめる
```

打つのは同じリポジトリ内の `assets/` と `data/` だけで、data: URI や外部URLには
触りません。すでに `?v=` が付いていれば付け替えるので、二重にはなりません。

なお `index.html` 自体も最大10分キャッシュされるため、**配備直後の数分は
古いままに見えることがあります**。そのときは再読み込みしてください。
10分を過ぎれば、あとは自動的に新しいURLを見に行きます。

## Search Console とアクセス解析

`github.io` のサブパスで配信しているため、Search Console は
**「ドメイン」ではなく「URL プレフィックス」**でしか登録できません
（ドメイン方式は DNS の TXT が要り、github.io の DNS は触れないため）。

手順と、`robots.txt` を置けない件、6サイトをまとめる方法は
[`docs/search-console.md`](docs/search-console.md) にまとめました。

アクセス解析は **Google アナリティクス 4**（[`docs/analytics.md`](docs/analytics.md)）。
`assets/config.js` の `analytics.measurementId` に測定IDを入れると動き、
**空のあいだは gtag.js を読み込みません**（外部への通信が1本も出ません）。
実装は [`assets/analytics.js`](assets/analytics.js) の1ファイルだけです。

**収録ゲーム5作すべてに同じ測定IDが入っています**（サイトに出しているのは3作ですが、
タグはインペリアルとレッドプラネットにも残してあります）。どのゲームが遊ばれているかを
1つのプロパティで見るためで、GA の「ページとスクリーン」でパスごとに分かれます。
ゲーム側は各 `index.html` の `<head>` にある `<script>` 1つだけで、
`file://` で開いたときは何も読み込みません。
測定IDを変えるときは**6か所とも**直す必要があります。

止め方を3つ用意してあります。ブラウザが追跡拒否（GPC / DNT）を出していれば
最初から読み込まず、奥付の「止める」を押せば `localStorage` に残って以後も読み込まず、
読み込み済みでも `ga-disable-<測定ID>` を立ててその場で送信を止めます。
そのぶん **GA の数字は実際の訪問より少なめに出ます**。

これに合わせて、奥付の「何も追跡せず」は消しました。
いまは何を集めるかを書き、**いまこの端末で実際に計測しているか**を状態から
書き出しています。書いてあることと、していることを食い違わせないためです。

## BGG の数字について

各ゲームに BoardGameGeek の**重さ（複雑さ 1〜5）**と**評価（1〜10）**を出しています。
これは**こちらの実測ではなく他人が付けた数字**なので、扱いを分けています。

- 色は藍だけ。朱（こちらの実測）と混ざらないようにする
- **取得日と評価人数を必ず添える**。BGG の値は日々動くので、載せた瞬間から古くなる
- 閲覧者のブラウザからは BGG を叩かない。取ってきた結果を `data/bgg.js` に
  コミットし、サイトはそれを読むだけ

### 運用 ── スナップショット方式

**BGG はデータセンターからの要求を 401 で弾きます。** 実測したところ、
`api.geekdo.com` / `boardgamegeek.com` / `www.boardgamegeek.com` の3宛先 ×
名乗り2種、**6通りすべてが 401** でした。GitHub のランナーもクラウド上の
開発環境もデータセンターなので、そこからは取得できません。

そこで、**取得と配信を切り離しています**。

```
  ご自分の回線で一度だけ取得  →  data/bgg.js に固める  →  サイトはそれを読むだけ
```

サイト側は BGG を一切叩きません。閲覧者のブラウザからも叩きません。
古くなったら取り直してコミットし直す、という運用です。

```sh
npm run bgg                              # 取得して data/bgg.js を書き換える
git add data/bgg.js && git commit && git push
```

Node を置いていない機械しか無いときは、どこか別の回線の機械で

```sh
npm run bgg:print                        # 書き込まず、中身だけ標準出力に出す
```

を走らせ、出てきたものを `data/bgg.js` に貼っても同じです。

ワークフロー（`.github/workflows/bgg.yml`）は手動実行の口だけ残してあります。
BGG の方針が変われば、そこから通るようになります。

なお BGG の XML API は <https://boardgamegeek.com/applications> での利用申請を
求めています。申請用の文面は [`docs/bgg-api-application.md`](docs/bgg-api-application.md)
に用意してあります（英文＋日本語訳）。**内容は `tools/fetch-bgg.mjs` の実装と
一致させてあるので、実装を変えたら申請文も直してください。** 申告と実際の
振る舞いがずれるのがいちばんまずい形です。

**スナップショットは古くなります。** だから画面には必ず取得日を出しています。
「いつの数字か」が見えないまま置かれた値ほど当てにならないものはありません。

JSON ではなく JS で書き出すのは、`fetch` を使わずに読めるようにするためです
（`file://` で開いても動く、という収録作と同じ性質を保ちます）。
照合は `bggName` で行い、取得した名前と発行年も残すので、別物を掴んでいれば一目で分かります。
`data/bgg.js` が空でも画面は壊れず、その行が出ないだけです。

### 読み取りの検査

通信は手元でしか通りませんが、**通ったあと正しく読めるか**は検査してあります
（`npm run test:parse`、通信なし）。実際に2件の取り違えを見つけて直しました。

- `<average>` の検索が **`<averageweight>` に当たっていた**。いまの BGG は
  average を先に出すので偶然そうならないだけで、順序が変われば
  「評価点のつもりで複雑さ」が黙って出るところだった
- `value=""` が **`Number('')` で 0 になっていた**。値が入っていない属性が
  「実測された 0」として出てしまう。本当に 0 のとき（評価が1件も無い新作）とは区別する
